**Version :** 1.0  
**Fichier cible recommandé :** `docs/00-master/MASTER-WASPLEX.md`  
**Nom du livrable officiel dans le dépôt :** `MASTER-WASPLEX.md`

**Nature :** carte générale du produit, de ses modules, de ses acteurs, de ses dépendances, de son modèle économique et de sa documentation  
**Dépendances :** notes officielles Wasplex 00 à 21  
**Principe central :** ce document oriente, relie et résume ; il ne remplace pas les spécifications détaillées de chaque module

# 1. Rôle du document maître

Le Document maître Wasplex est la porte d’entrée officielle du projet.

Il permet de comprendre rapidement :

- ce qu’est Wasplex ;
- à qui Wasplex s’adresse ;
- comment l’application est organisée ;
- comment la valeur circule ;
- quels sont les modules ;
- quelles sont leurs dépendances ;
- quelle est la stack technique ;
- quels documents lire ;
- dans quel ordre travailler ;
- où trouver la source détaillée d’une décision.

---

# 2. Ce que le document maître n’est pas

Il n’est pas :

- une reprise complète de toutes les notes ;
- une constitution ;
- une doctrine ;
- un texte juridique ;
- un cahier des charges exhaustif d’un seul module ;
- une roadmap technique détaillée ;
- un substitut au dépôt ;
- une justification pour bloquer le codage.

---

# 3. Hiérarchie documentaire

La documentation Wasplex fonctionne ainsi :

```text
Document maître
→ donne la vision générale et la carte du système

Notes fonctionnelles
→ définissent chaque module en détail

Architecture technique
→ définit les règles d’assemblage

Feuille de route
→ définit l’ordre réel d’implémentation après audit

Dépôt
→ contient l’implémentation

Rapports de chantier
→ prouvent les travaux réalisés
```

---

# 4. Ordre de priorité des sources

En cas de doute :

```text
1. décision explicite du fondateur
2. note officielle du module
3. architecture technique officielle
4. roadmap validée
5. code réel du dépôt
6. ancienne documentation
```

Une divergence importante doit être signalée.

Wasplex permet à une personne :
